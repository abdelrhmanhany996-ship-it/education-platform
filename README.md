# المنصة التعليمية الأكاديمية

واجهة React + خادم Node (Express) + قاعدة بيانات Firebase Firestore + إرسال واتساب مباشر عبر WhatsApp Cloud API.

## التشغيل

**أسرع طريقة:** على Windows اضغط مرتين على `start-local.bat`، وعلى Mac/Linux شغّل `./start-local.sh`. السكريبت يحدّث المشروع ويثبّت الحزم ويشغّل المنصة ويفتح http://localhost:3000 في المتصفح.

```bash
npm install --legacy-peer-deps
npm run dev          # http://localhost:3000  (أو npm run dev -- --port=3001)
```

بدون أي إعداد يعمل التطبيق فوراً ويحفظ بياناته في ملف محلي `server/data/db.json`، وتظهر على الشاشة الرئيسية حسابات تجريبية للدخول بضغطة واحدة (كلمة مرور الحسابات كلها `123456`). الدكتور: `doctor`.

للاستخدام الفعلي أكمل الخطوتين التاليتين، ثم انسخ `.env.example` إلى `.env`.

## 1) ربط Firebase (قاعدة البيانات)

1. ادخل [console.firebase.google.com](https://console.firebase.google.com) وأنشئ مشروعاً.
2. من **Build → Firestore Database** اضغط **Create database** (وضع الإنتاج Production mode يكفي، فالخادم هو الذي يقرأ ويكتب).
3. من **Project settings → Service accounts** اضغط **Generate new private key** وسيُنزّل ملف JSON.
4. ضع الملف داخل هذا المجلد باسم `firebase-service-account.json`.
5. في `.env`:
   ```
   FIREBASE_SERVICE_ACCOUNT=firebase-service-account.json
   ```
6. أعد تشغيل `npm run dev`. عند التشغيل الأول تُحمَّل البيانات التجريبية في Firestore، وتظهر في الطرفية عبارة `Storage: Firebase Firestore`.

> المتصفح لا يتصل بـ Firebase أبداً. كل القراءة والكتابة تمر عبر الخادم، ومفتاح الخدمة يبقى عليه فقط.
> ملف المفتاح يعطي صلاحية كاملة على قاعدة بياناتك. لا ترفعه إلى GitHub (وهو مستثنى في `.gitignore`).

### فيديوهات المحاضرات (Cloudflare Stream) — موصى به

عند ضبط متغيرات Cloudflare يتولى **Cloudflare Stream** تخزين الفيديو وتحويله وبثه (HLS متكيّف مع سرعة الإنترنت عبر CDN). ملف الفيديو لا يمر على خادم المنصة إطلاقاً، ويُحفظ في Firestore معرّف الفيديو (`videoUid`) وحالته ومدته فقط.

| المتغير | القيمة |
|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | من لوحة Cloudflare |
| `CLOUDFLARE_STREAM_API_TOKEN` | API Token بصلاحية **Stream: Edit** (يبقى على الخادم فقط) |
| `CLOUDFLARE_STREAM_CUSTOMER_CODE` | الجزء `xxxx` من `customer-xxxx.cloudflarestream.com` |
| `CLOUDFLARE_STREAM_SIGNING_KEY_ID` / `CLOUDFLARE_STREAM_SIGNING_KEY_PEM` | مفتاح توقيع (اختياري لكنه موصى به: يوقّع روابط التشغيل محلياً بدون طلب API لكل مشاهدة) |
| `CLOUDFLARE_STREAM_ALLOWED_ORIGINS` | اختياري: نطاق موقعك فقط، مثل `lms.example.com` |

إنشاء مفتاح التوقيع مرة واحدة:
```
curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/stream/keys" \
  -H "Authorization: Bearer $CLOUDFLARE_STREAM_API_TOKEN"
```
ضع `result.id` في `CLOUDFLARE_STREAM_SIGNING_KEY_ID` و`result.pem` كما هو في `CLOUDFLARE_STREAM_SIGNING_KEY_PEM`.

**الرفع:** الدكتور يطلب من الخادم رابط رفع لمرة واحدة، ثم يرفع المتصفح الملف مباشرة إلى Cloudflare على أجزاء (TUS) حتى 30 جيجابايت. الرفع يعمل في الخلفية مع شريط تقدم وإمكانية الإلغاء، ويُعاد كل جزء تلقائياً عند انقطاع الإنترنت. لو أُغلقت الصفحة أثناء الرفع، اختر نفس الملف مرة أخرى فيكمل من حيث توقف. الحالات: `uploading` ثم `processing` ثم `ready` أو `failed`.

**المشاهدة:** كل فيديو يُنشأ بخاصية `requireSignedURLs`. بعد التأكد من تسجيل الطالب في المقرر ونشر المحاضرة، يعطيه الخادم رمز تشغيل موقّعاً قصير العمر (مدة الفيديو + 15 دقيقة، بين 30 دقيقة و4 ساعات) **بدون صلاحية تنزيل MP4**. معرّف الفيديو وحده لا يشغّل شيئاً، والمشغّل يجدد الرمز تلقائياً عند انتهائه.

بدون متغيرات Cloudflare تعمل المنصة بالطريقة البديلة التالية.

### البديل: الملفات على Firebase Cloud Storage / الخادم

- عند الاتصال بـ Firestore تُحفظ الفيديوهات وملفات PDF في Bucket خاص على Firebase Cloud Storage (المسار `private/lecture-files/`)، ويظهر في الطرفية `Files: private Cloud Storage bucket`. بدون Firestore تُحفظ في `server/data/uploads`.
- اسم الـ Bucket يُقرأ من `firebase-applet-config.json` أو من `FIREBASE_STORAGE_BUCKET`. القيمة `off` تُبقي الملفات على القرص المحلي.
- حساب الخدمة يحتاج صلاحية **Storage Object Admin** على الـ Bucket.
- انشر قواعد `storage.rules` (تمنع أي قراءة أو كتابة مباشرة من المتصفح): `firebase deploy --only storage`.
- الملفات التي لم تعد أي محاضرة تستخدمها (رفع فشل حفظه، فيديو تم استبداله) تُحذف تلقائياً بعد 24 ساعة.

## 2) ربط واتساب (الإرسال المباشر)

الإرسال يتم من الخادم عبر **WhatsApp Cloud API** الرسمي من Meta:

1. ادخل [developers.facebook.com](https://developers.facebook.com) وأنشئ تطبيقاً من نوع **Business** وأضف له منتج **WhatsApp**.
2. من **WhatsApp → API Setup** انسخ:
   - **Phone number ID** إلى `WHATSAPP_PHONE_NUMBER_ID`
   - **Temporary access token** إلى `WHATSAPP_TOKEN` (صالح 24 ساعة للتجربة. للاستخدام الدائم أنشئ **System User** من Business Settings وولّد له رمزاً دائماً بصلاحية `whatsapp_business_messaging`).
3. في وضع التجربة لا تصل الرسائل إلا للأرقام المضافة في **To → Manage phone number list**. أضف رقمك ورقم طالب للاختبار.
4. أعد تشغيل الخادم. في مودال الرسالة سيعمل زر **إرسال**.

### قاعدة الـ 24 ساعة (مهم)

واتساب يسمح بنص حر فقط لمن راسل رقمك خلال آخر 24 ساعة. غير ذلك يجب استخدام **قالب معتمد**:

1. من **WhatsApp Manager → Message templates** أنشئ قالباً (فئة Utility) بلغة العربية، ونصه متغير واحد فقط:
   ```
   {{1}}
   ```
2. بعد اعتماده ضع اسمه في `WHATSAPP_TEMPLATE_NAME` (واللغة في `WHATSAPP_TEMPLATE_LANG`).

عندها يحاول الخادم إرسال النص أولاً، وإذا رفضه واتساب لهذا السبب أعاد الإرسال بالقالب تلقائياً.

### الزرّان في مودال الرسالة

| الزر | ما يفعله |
|---|---|
| **إرسال** | يرسل فوراً من الخادم عبر Cloud API ويسجّل النتيجة في **التنبيهات والرسائل**. لا يفتح واتساب. |
| **شات الواتس** | يفتح المحادثة في واتساب برسالة جاهزة لتكتب وترسل بنفسك. لا يُسجَّل ولا يُحتسب من الحد الأسبوعي. |

حالة "أُرسلت" تعني أن Meta قبلت الرسالة. إشعارات التسليم والقراءة تحتاج Webhook على رابط عام، وهذا غير متاح في التشغيل المحلي.

## الأمان

- كلمات المرور تُخزَّن مشفّرة (scrypt) ولا تصل للمتصفح أبداً. الدخول برمز موقّع يبقى 12 ساعة.
- الطالب يقرأ بياناته فقط، ولا يرى هواتف زملائه ولا إجاباتهم، ويكتب في سجل تقدمه هو فقط. الدكتور وحده يكتب باقي البيانات ويرسل واتساب.
- التسجيل العام للطلاب فقط. حسابات الدكاترة يضيفها دكتور من **الإعدادات**.
- **حماية الفيديو:** مع Cloudflare Stream: رموز تشغيل موقّعة قصيرة العمر بدون صلاحية تنزيل، ويتحقق الخادم أن الفيديو يخص دكتور المقرر نفسه. في الوضع البديل: لا يحصل الطالب أبداً على رابط دائم أو رابط Storage. الخادم يتحقق من تسجيله في المقرر ومن نشر المحاضرة، ثم يعطيه رابط تشغيل صالحاً 15 دقيقة (`VIDEO_GRANT_MINUTES`) ومربوطاً بحسابه ومتصفحه، ويُبث الفيديو على أجزاء. فتح الرابط في تبويب جديد أو من متصفح آخر يُرفض، ولا يوجد زر تحميل، ويظهر اسم الطالب كعلامة مائية متحركة. المشغل يجدد الرابط تلقائياً ويكمل من نفس الثانية.
- لا توجد حماية كاملة 100% في المتصفح: يمكن دائماً تسجيل الشاشة أو التقاط البيانات بأدوات متقدمة. الهدف منع التحميل العادي والروابط الدائمة والوصول غير المصرّح به.
- **قبل استخدام حقيقي:** ضع `ALLOW_DEMO_LOGIN=false` في `.env` لتعطيل الدخول بضغطة واحدة، وشغّل الخادم خلف HTTPS.

### ما لم يُنقل للخادم بعد

- تصحيح الكويز ما زال في المتصفح، وبنك الأسئلة (بإجاباته الصحيحة) يصل لمتصفح الطالب. طالب متمكن تقنياً يستطيع رؤيتها أو تعديل درجته.
- مواعيد فتح وإغلاق الكويز تُفحص في المتصفح.

الخطوة التالية لإصلاح ذلك: نقل بدء الكويز وتسليمه وتصحيحه إلى الخادم، وعدم إرسال الإجابات الصحيحة للطالب.
